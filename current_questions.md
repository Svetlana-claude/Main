## 1. Записывать ли выявленный технический долг

**Вопрос:** внести ли в `tech_debt.md` три позиции, найденные при сдаче проекта 1?

1. **Самоподписанный сертификат.** Браузер показывает предупреждение при первом входе.
   Грозит привычкой нажимать «всё равно продолжить», а это гасит смысл проверки
   сертификата. Закрывается переходом на домен с Let's Encrypt — решение 3.2 (б).
2. **Приложение и Claude Code работают от пользователя `mokeeva` без изоляции.**
   Проект с поднятым флагом `allow_bash` может всё, что может пользователь, включая
   правку файлов вне каталога проекта. Грозит тем, что ошибка в задаче затронет
   систему целиком. Закрывается запуском под отдельным пользователем с урезанными
   правами либо контейнером.
3. **Резервного копирования базы нет.** Вся история диалогов, расходов и настроек
   живёт в одном экземпляре PostgreSQL без снимков. Грозит полной потерей при сбое
   диска. Закрывается регулярным `pg_dump` по расписанию.

**Почему возник:** правило 4 требует спрашивать перед записью в `tech_debt.md`.

**Что предлагается:** записать все три в формате «что не так → чем грозит →
как закрывается».
