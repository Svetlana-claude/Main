# `webclaude.md` — как построить такой же веб-интерфейс

Свод всего, что нужно, чтобы повторить рабочее место поверх Claude Code с нуля:
стек, структура, схема базы, устройство движка, правила работы, развёртывание и
грабли, на которых уже потоптались. Документ самодостаточный — по нему можно
собрать интерфейс на другой машине, не заглядывая в исходный репозиторий.

Действующий образец: `https://mokeevasky.ru/Claude`, каталог `webui/`.

---

## 1. Что это и главное решение

Пульт к Claude Code через браузер: замена терминала для повседневной работы.
Вход по паролю, дашборд с метриками сервера и расходом токенов, «Чатики» для
разговоров и «Проекты» с темами, в которых Claude правит файлы рабочего каталога.

**Ключевое решение — приложение не обращается к Messages API и не реализует
инструменты заново.** Оно запускает тот же `claude`, что работает в терминале,
в неинтерактивном режиме (`-p` с `--output-format stream-json`) и разбирает поток
JSON. Отсюда два следствия:

* аутентификация — по подписке, отдельный API-ключ не нужен и не хранится;
* правила из `CLAUDE.md`, скиллы и память подхватываются сами.

Второе решение того же порядка: **чатики и темы проектов работают на одном
движке**, разница только в правах. Одна таблица `conversations`, один драйвер,
одна страница диалога — сообщения, поиск и экспорт получаются общими бесплатно.

Повторять это имеет смысл там, где есть свой сервер и подписка, а строить свой
агент поверх API не хочется.

## 2. Предпосылки

| Что | Значение в образце |
|---|---|
| Сервер | Ubuntu 24.04, 2 ядра, 2.9 ГБ RAM, 40 ГБ диск |
| Пользователь | `mokeeva`, от него же работают служба и `claude` |
| Claude Code | установлен и **авторизован по подписке** в домашнем каталоге (`~/.claude`) |
| Домен | нужен для TLS от Let's Encrypt; без домена — самоподписанный сертификат |

Проверить до начала: `claude -p "привет" --output-format stream-json --verbose`
из-под того же пользователя должен отдать поток JSON, не спрашивая ничего.
Если спрашивает — интерфейс повиснет: нажимать кнопки будет некому.

## 5. Адреса и монтирование

## 6. База

Девять таблиц. Схема применяется идемпотентно при каждом старте — миграций как
отдельного механизма нет, добавление столбца пишется как
`ALTER TABLE ... ADD COLUMN IF NOT EXISTS`.

| Таблица | Назначение |
|---|---|
| `users` | пользователь, хеш argon2id, признак обязательной смены пароля |
| `sessions` | серверные сессии: выход завершает сессию по-настоящему |
| `login_attempts` | защита от перебора пароля |
| `projects` | проекты, рабочий каталог, флаг `allow_bash` |
| `conversations` | чатики и темы, `claude_session_id` для продолжения |
| `messages` | сообщения с расходом токенов, `content_tsv` для поиска (GIN) |
| `files` | файлообмен по проектам |
| `settings` | параметры приложения ключ-значение |
| `metrics_history` | история метрик для графика |

Ключевое место — единая таблица диалогов с проверкой согласованности вида
и проекта:

```sql
CREATE TABLE IF NOT EXISTS conversations (
    id                serial PRIMARY KEY,
    kind              text NOT NULL CHECK (kind IN ('chat', 'topic')),
    project_id        integer REFERENCES projects(id) ON DELETE CASCADE,
    title             text NOT NULL,
    claude_session_id text,                 -- для --resume, продолжения диалога
    created_at        timestamptz NOT NULL DEFAULT now(),
    updated_at        timestamptz NOT NULL DEFAULT now(),
    CONSTRAINT conversations_kind_project CHECK (
        (kind = 'chat'  AND project_id IS NULL) OR
        (kind = 'topic' AND project_id IS NOT NULL)
    )
);
```

Сообщения хранят расход по каждому ответу — из него собирается дашборд, —
и сразу готовый вектор для полнотекстового поиска:

```sql
CREATE TABLE IF NOT EXISTS messages (
    id               bigserial PRIMARY KEY,
    conversation_id  integer NOT NULL REFERENCES conversations(id) ON DELETE CASCADE,
    role             text NOT NULL CHECK (role IN ('user', 'assistant', 'error')),
    content          text NOT NULL,
    created_at       timestamptz NOT NULL DEFAULT now(),
    model            text,
    input_tokens     integer NOT NULL DEFAULT 0,
    output_tokens    integer NOT NULL DEFAULT 0,
    cache_read       integer NOT NULL DEFAULT 0,
    cache_write      integer NOT NULL DEFAULT 0,
    cost_usd         numeric(12, 6) NOT NULL DEFAULT 0,
    duration_ms      integer NOT NULL DEFAULT 0,
    num_turns        integer NOT NULL DEFAULT 0,
    content_tsv      tsvector GENERATED ALWAYS AS (to_tsvector('russian', content)) STORED
);
CREATE INDEX IF NOT EXISTS messages_tsv_idx ON messages USING gin(content_tsv);
```

Поиск идёт через `websearch_to_tsquery('russian', …)` с `ts_headline` для
подсветки и `ts_rank` для порядка.

Пул соединений держится скромным (`min_size=1, max_size=8`) — это ограничение
памяти, а не производительности. Строки читаются словарями (`row_factory=dict_row`),
чтобы шаблоны обращались к полям по имени.

## 7. Драйвер движка — сердце системы

### Сборка командной строки

```python
argv = [
    CLAUDE_BIN, "-p", prompt,
    "--output-format", "stream-json",
    "--include-partial-messages",
    "--verbose",
    "--model", model,
]
if session_id:
    argv += ["--resume", session_id]       # продолжение того же диалога

if with_tools:                             # тема проекта
    allowed = ["Read", "Write", "Edit", "Glob", "Grep", "WebSearch", "WebFetch"]
    denied  = SECRET_DENY
    if allow_bash:
        allowed.append("Bash")
    else:
        denied += ["Bash", "BashOutput", "KillShell"]
    argv += ["--disallowed-tools", *denied]
    argv += ["--allowed-tools", *allowed]
    argv += ["--permission-mode", "acceptEdits"]
    argv += ["--add-dir", str(workdir)]
else:                                      # чатик: инструменты выключены
    argv += ["--disallowed-tools", "Bash", "Edit", "Write", "Read", "Glob",
             "Grep", "WebSearch", "WebFetch", "NotebookEdit", "Task", *SECRET_DENY]

argv += ["--permission-prompts", "none"]   # нажимать кнопки некому
```

### Пять граблей, на которых уже потоптались

1. **`--allowed-tools` не запрещает остальное.** Он только авто-одобряет
   перечисленное. С одним этим флагом `Bash` выполняется. Запрет даёт только
   явный `--disallowed-tools`, и запрещать надо всё семейство сразу —
   `Bash`, `BashOutput`, `KillShell`, иначе запрет обходится соседним
   инструментом. *Проверено нажатием: без явного запрета команда проходила.*
2. **`--add-dir` задаёт рабочую область, но не границу.** Перечисленный
   в `--allowed-tools` `Read` авто-одобряет чтение **любого** пути. Запрет
   по пути нужен явный: `Read(//путь/**)`, `Write(//путь/**)`, `Edit(//путь/**)`.
3. **Двойной слеш обязателен.** Абсолютный путь в правиле пишется как
   `//home/...`. С одним слешем правило **молча не срабатывает** — отказа не
   видно, файл просто читается.
4. **Штатный `readline()` не годится.** У `asyncio.StreamReader` буфер 64 КиБ,
   а движок кладёт в одну строку JSON и содержимое прочитанного файла, и вывод
   команды, и текст ответа целиком. Падает с «Separator is not found, and chunk
   exceed the limit», а на странице это выглядит как «Сбой обработки». Нужен
   свой построчный разбор без ограничения на длину, с потолком (64 МБ) на
   выброс нештатной строки. Тайм-аут при этом считается **на кусок**, а не на
   строку: это время молчания движка.
5. **В `modelUsage` попадает и вспомогательная модель** (haiku на служебные
   операции). Брать первый ключ нельзя, порядок произвольный: основной считается
   та, что выдала больше всего токенов на выход.

### События потока

Драйвер — асинхронный генератор, отдающий словари: `init` (пришёл
`session_id`), `delta` (кусок текста из `content_block_delta`), `usage`
(накопительный расход шага из `message_start` / `message_delta`), `tool`
(вызов инструмента), `text` (готовый текст шага), `result` (итог с расходом,
стоимостью, длительностью и числом шагов), `error`.

Итоговое событие `result` — единственное место, где ответ попадает в базу.
Из него же берутся `total_cost_usd`, `usage` (вход, выход, чтение и запись
кэша) и `num_turns`.

Предел на один ответ — **30 минут** (`RUN_TIMEOUT_SEC = 1800`): агентская
работа бывает долгой. Столько же держит соединение nginx.

### Заголовок диалога

Отдельный дешёвый вызов на haiku по первой реплике: «Новый чат» через неделю
ничего не говорит. Запускается после ответа, результат уходит в браузер
событием `title`.

## 8. Фоновые запуски: уход со страницы не должен обрывать работу

Самая дорогая ошибка проекта и её разбор.

**Как было.** Ответ движка шёл прямо в теле HTTP-ответа: `StreamingResponse`
с генератором, который сам же и запускал `claude`. Переход на другую вкладку —
обычная навигация браузера: соединение закрывается, Starlette отменяет
генератор, драйвер гасит процесс. Работа обрывалась, и ответ пропадал совсем:
в базу он пишется по событию `result`, а до него дело не доходило.

**Как надо.** Запуск живёт в задаче приложения и о браузере ничего не знает:

* `POST …/send` кладёт вопрос в базу, заводит фоновую задачу и **сразу**
  отвечает `{"ok": true}`;
* события копятся в списке объекта `Run`, ожидание — через `asyncio.Condition`;
* `GET …/stream?start=N` — только читатель: отдаёт события с позиции `N`
  кадрами SSE и может быть оборван и открыт заново;
* браузер считает позицию сам и при обрыве сети переподключается с той же,
  не пересчитывая показанное.

**Почему список, а не очередь.** Очередь читается один раз, и вернувшийся
браузер получил бы обрывок с середины. Список хранит весь ответ, поэтому
страница восстанавливает его с начала.

Тонкости, без которых оно ведёт себя странно:

* законченный запуск держится ещё **30 минут** — иначе, отойдя на пять минут,
  человек вернётся к пустому месту вместо удавшегося ответа;
* при **открытии** страницы поток запрашивается с признаком `active=1`:
  иначе прошлый ответ проигрался бы заново поверх того же ответа, уже
  показанного из базы;
* разговора без запуска не бывает только на первый взгляд — если отвечать
  нечего, сервер сразу шлёт `idle`, иначе браузер будет ждать событий,
  которых не будет;
* предохранитель от разрастания памяти: 20 000 событий на ответ, дальше в ленту
  кладётся отметка об обрыве показа. Молча обрывать нельзя — страница решит,
  что ответ таков;
* повторная отправка при идущем ответе отклоняется с 409 **до** записи вопроса
  в базу: иначе вопрос повис бы в ленте без ответа и выглядел бы потерянным;
* перезапуск службы фоновый запуск не переживает, и это учтено в разделе 11.

Кадр SSE: `data: {json}\n\n`, в конце — `{"type": "done"}`.
Со стороны nginx обязательны `proxy_buffering off` и заголовок
`X-Accel-Buffering: no`, иначе поток копится в буфере и приходит разом.

## 9. Права в проектах

Правка файлов в каталоге проекта разрешена всегда
(`--permission-mode acceptEdits`) — иначе тема бесполезна. Запуск команд —
только при `projects.allow_bash`, переключателем на странице проекта.

Рабочий каталог проекта создаётся по `slug`, полученному транслитерацией имени.
**Если каталог уже существует, проект заводится записью в таблице с нужным
slug, а не формой** — иначе «Веб-интерфейс» даст `veb-interfeys/` рядом с уже
существующим `webui/`.

Сам интерфейс полезно завести проектом в самом себе: тогда его можно
дорабатывать из браузера. `allow_bash` при этом поднимается осознанно — без
права запускать команды правку кода нечем применить и не на чем проверить.

## 10. Секреты

`SECRET_KEY` и пароль базы лежат в `~/.config/webui/webui.env` (права 600) —
**вне** каталога проекта, потому что `webui/` это рабочий каталог темы.
Путь переопределяется переменной `WEBUI_ENV`. В репозитории — только
`.env.example` с образцом состава:

```
DATABASE_URL=postgresql://webui:ПАРОЛЬ@127.0.0.1:5432/webui
SECRET_KEY=случайные_64_hex_символа
CLAUDE_BIN=/home/mokeeva/.local/bin/claude
REPO_ROOT=/home/mokeeva/main
ROOT_PATH=/Claude
```

**Одного выноса мало. Нужны три вещи разом:**

1. файл вне каталога проекта — иначе он в области работы темы;
2. явный запрет по пути на `Read`/`Write`/`Edit` с двойным слешем — иначе
   читается по абсолютному пути;
3. вычистка окружения перед запуском `claude`: dotenv кладёт значения
   в `os.environ`, и дочерний процесс наследует их — `env` показал бы ключи
   вообще без доступа к файлу.

Список вычищаемых имён задаётся **явно**, а не собирается из файла настроек.
Иначе после переноса ключей в `EnvironmentFile` юнита файла у пользователя
не будет, набор окажется пустым — и вычистка откажет ровно тогда, когда она
единственное, что защищает ключи.

**Чего это не закрывает.** При поднятом `allow_bash` команда `cat` читает файл
где бы он ни лежал: запрет по пути действует на инструменты работы с файлами,
но не на содержимое команд. Полное решение — вынести ключи в `/etc/webui/webui.env`
под root с правами 600 и подключить их врезкой юнита:

```ini
[Service]
EnvironmentFile=/etc/webui/webui.env
```

Тогда доступного пользователю файла нет вовсе, значения приходят от systemd,
а до `claude` не доходят. Ставится вручную с паролем: правка юнитов
в беспарольный sudo не входит и входить не должна.

**Остаточный риск, который надо назвать вслух:** приложение и `claude` работают
от одного пользователя без изоляции. Тема с `allow_bash` — это доступ к
командной строке этого пользователя. Настоящее решение — отдельный пользователь
с собственным домашним каталогом либо контейнер.

### Вход и сессии

* пароли — argon2id (`time_cost=3, memory_cost=65536, parallelism=2`: 64 МБ на
  проверку, с запасом по стойкости и без удара по памяти сервера);
* сессии серверные: идентификатор в подписанной cookie (`itsdangerous`), сама
  запись в базе — поэтому выход действительно завершает сессию, а в настройках
  видны активные входы и их можно закрыть;
* первый вход по паролю из ТЗ, смена **обязательна**: до неё все страницы
  уводят на форму смены;
* проверка стойкости: длина, не первоначальный, не одни цифры, не из списка
  ходовых;
* защита от перебора: таблица `login_attempts` плюс `limit_req` в nginx на
  `/Claude/login` (12 запросов в минуту, всплеск 5);
* IP берётся из `X-Forwarded-For` — перед приложением nginx.

## 11. Перезапуск приложения из интерфейса

Правка кода применяется только перезапуском службы, а сделать это прямо из темы
нельзя: `claude` запущен приложением и потому входит в контрольную группу
`webui.service`. Остановка службы гасит группу целиком — вместе с процессом,
который в этот момент готовит ответ, а ответ пишется в базу по завершении.

Поэтому кнопка **ставит перезапуск в очередь**: драйвер считает выполняющиеся
ответы, служба уходит на перезапуск только когда счётчик обнулился. Предел
ожидания — те же 30 минут. Браузер опрашивает состояние, ловит момент, когда
приложение перестало отвечать, и обновляет страницу, как только `/healthz`
снова отвечает.

Задание переживает гибель заказчика: `systemctl` отдаёт его systemd по шине
и только ждёт результата, а сама остановка убивает ожидающий процесс.
Команда вызывается **дословно** в том виде, в каком разрешена в sudoers:
`/usr/bin/sudo -n /usr/bin/systemctl restart webui`.

## 12. Учёт расхода

`claude` после каждого запуска возвращает `total_cost_usd`, `usage` и
`modelUsage`. Это пишется в `messages` и суммируется на дашборде.

**Остаток по подписке получить нельзя.** Счёт ведётся на стороне Anthropic,
программного способа спросить остаток нет: Admin и Analytics API личным
подпискам не выдаются, у телеметрии метрики остатка нет. Остаток показывают
только `/status` и `/usage` внутри живой сессии. Поэтому предел окна задаётся
в настройках и **подбирается наблюдением**: выдуманный предел показывал бы
уверенный остаток, которого никто не обещал.

**Деньги — не то, что ограничивает.** Подписка не тарифицируется по запросам;
ограничивают окна — на 5 часов и на неделю. `total_cost_usd` это пересчёт по
тарифам API, «сколько стоило бы то же самое без подписки», — справочная строка,
не главное число.

**Откуда брать расход.** Своя таблица знает только то, что прошло через
интерфейс, а запуски `claude` из терминала расходуют окно наравне. Поэтому окна
считаются по стенограммам сессий `~/.claude/projects/<проект>/<сессия>.jsonl`,
которые движок пишет всегда, а база остаётся запасным источником. Какой
источник сработал — написано на самой странице: дашборд, который врёт молча,
хуже отсутствующего.

⚠️ **Главная ловушка стенограмм — двойной счёт.** Один ответ разложен на
несколько строк (рассуждение, текст, вызовы инструментов), и в каждой лежит
**один и тот же** блок `usage` — не доля, а полный расход ответа. Построчное
сложение завышает счёт больше чем вдвое (на здешних файлах 1 275 строк давали
1 229 685 выходных токенов вместо настоящих 554 316 по 632 ответам). Строки
сводятся по ключу `requestId + message.id`; `uuid` для этого не годится —
он у каждой строки свой.

Файлы дочитываются с прошлого места по смещению: на автообновлении раз в 10
секунд перечитывать растущую стенограмму целиком незачем. Последняя строка
бывает обрезана на середине — берётся только то, что закончилось переводом
строки.

Окно скользящее и начинается с первого запроса, а не в круглый час: начало —
самый ранний ответ внутри длины окна, обнуление — начало плюс длина.

Метрики сервера берутся из psutil и `/proc` и намеренно совпадают с тем, что
показывают `free`, `df` и `uptime`: иначе дашборд врёт, а проверить его нечем.
`cpu_percent(interval=None)` даёт загрузку с прошлого вызова — не блокирует
ответ на секунду. Скорость сети считается самостоятельно: psutil даёт счётчики.

## 13. Дизайн-система

Плотные таблицы, командные панели, тёплая серо-бежевая гамма, жёлто-оранжевый
акцент, минимум декора: без скруглений и теней. Всё на CSS-токенах — тёмная
тема переопределяет только их, и ни одно правило больше не трогается.

```css
:root {
    --bg: #f2f1ee;  --bg-sunken: #e7e5e0;  --panel: #ffffff;  --panel-alt: #faf9f7;
    --cmdbar: linear-gradient(#f7f6f3, #eceae4);  --cmdbar-flat: #f1efea;
    --line: #c9c6bf;  --line-soft: #dedbd4;  --line-strong: #a8a49b;
    --ink: #23211d;  --ink-soft: #5f5b53;  --ink-faint: #8b867c;  --ink-invert: #fff;
    --accent: #e8b000;  --accent-deep: #b98a00;  --accent-wash: #fdf4d0;
    --link: #1f5c9e;  --link-hover: #14406e;
    --ok: #2f7d32;  --warn: #b26a00;  --err: #b3261e;
    --row-hover: #f5f2e6;  --row-select: #fdf3cd;
    --gap: 8px;  --radius: 2px;          /* скруглений почти нет — так в 1С */
    --font: "Segoe UI", "PT Sans", Tahoma, sans-serif;
    --fs: 13px;  --fs-sm: 12px;  --row-h: 26px;
}
```

Тема переключается тремя состояниями: `light`, `dark`, `system`. Светлая и
тёмная задаются через `:root[data-theme="…"]`, системная — через
`@media (prefers-color-scheme: dark)` с оговоркой `:root:not([data-theme="light"])`,
иначе явно выбранная светлая тема ночью самовольно темнеет.

Раскладка: `base.html` даёт титульную строку, панель разделов и блок `main`,
страницы переопределяют `content` либо целиком `layout` — окно диалога занимает
ровно высоту окна, лента прокручивается внутри себя, поле ввода стоит внизу.

**Окно диалога.** Промежуточные действия («инструмент: Bash») выведены из ленты
в отдельный блок «Ход работы»: лента остаётся разговором. В проектах правая
колонка делится надвое — сверху «Файлы», снизу ход работы со своей прокруткой.
В информационной строке блока — таймер, счётчик шагов и живой расход токенов,
после завершения — время, стоимость и итог. Ctrl+Enter отправляет.

Прокрутка «липнет» к низу только если пользователь и так внизу (запас 60 px):
иначе чтение предыдущего ответа сбивалось бы каждым новым куском текста.

Вёрстка: семантические теги, адаптивность, доступность (осмысленные `alt`,
контраст, фокус с клавиатуры). Широкие блоки — таблицы, диаграммы, код —
скроллятся внутри своего контейнера, страница по горизонтали не едет.

Тексты интерфейса и комментарии в коде — **на русском**. Стиль имён:
PascalCase для классов и компонентов, camelCase для локальных переменных и
функций, kebab-case для CSS-классов и имён файлов.

## 14. Развёртывание

### nginx

Весь HTTP уводится на HTTPS — пароль не должен уходить открытым текстом.
Исключение одно: `location ^~ /.well-known/acme-challenge/` для проверки
владения доменом, её уводить на HTTPS нельзя (доверенного сертификата ещё нет).
`^~` важен: иначе сработает редирект из `location /`.

```nginx
location = /Claude/login {
    limit_req zone=login burst=5 nodelay;
    proxy_pass http://127.0.0.1:8000/login;
    include /etc/nginx/snippets/webui-proxy.conf;
}

location /Claude/ {
    proxy_pass http://127.0.0.1:8000/;
    include /etc/nginx/snippets/webui-proxy.conf;
    proxy_buffering off;          # поток ответа не должен копиться в буфере
    proxy_cache off;
    proxy_read_timeout 1800s;     # агентская работа бывает долгой
    proxy_send_timeout 1800s;
}

location = /Claude { return 301 /Claude/; }
location = /       { return 301 /Claude/; }
location /         { return 404; }
```

Снипет прокси:

```nginx
proxy_http_version 1.1;
proxy_set_header Host              $host;
proxy_set_header X-Real-IP         $remote_addr;
proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
proxy_set_header X-Forwarded-Proto $scheme;
proxy_set_header Connection        "";
```

Зона ограничения (в `conf.d`, вне `server`):
`limit_req_zone $binary_remote_addr zone=login:1m rate=12r/m;`

Заголовки безопасности: `X-Content-Type-Options nosniff`,
`X-Frame-Options SAMEORIGIN`, `Referrer-Policy same-origin`.
`client_max_body_size 70m` — чуть больше предела загрузки в приложении (64 МБ).

Адрес с `www` уводится на основной **редиректом, а не вторым рабочим именем**:
cookie привязана к имени, иначе вход под www и без него оказались бы разными
сеансами — и это выглядело бы как случайный разлогин.

### systemd

```ini
[Unit]
Description=Веб-интерфейс рабочего места
After=network.target postgresql.service
Wants=postgresql.service

[Service]
Type=simple
User=mokeeva
Group=mokeeva
WorkingDirectory=/home/mokeeva/main/webui
Environment=PATH=/home/mokeeva/main/webui/.venv/bin:/home/mokeeva/.local/bin:/usr/local/bin:/usr/bin:/bin
ExecStart=/home/mokeeva/main/webui/.venv/bin/uvicorn app.main:app \
    --host 127.0.0.1 --port 8000 --root-path /Claude \
    --proxy-headers --forwarded-allow-ips 127.0.0.1
Restart=on-failure
RestartSec=3
# Приложение запускает claude, которому нужен домашний каталог с учётными данными
Environment=HOME=/home/mokeeva
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

`HOME` задавать обязательно: без него `claude` не найдёт учётные данные
подписки и каждый ответ будет падать на авторизации.

### Установка с нуля

```bash
sudo apt-get install -y postgresql nginx python3-venv python3-dev libpq-dev
sudo -u postgres createuser webui --pwprompt
sudo -u postgres createdb -O webui webui
cd /home/mokeeva/main/webui
python3 -m venv .venv && ./.venv/bin/pip install -r requirements.txt
install -d -m 700 ~/.config/webui
install -m 600 .env.example ~/.config/webui/webui.env   # заполнить значения
# схема применяется сама при первом запуске
sudo cp deploy/webui.service /etc/systemd/system/webui.service
sudo cp deploy/nginx-webui.conf /etc/nginx/sites-available/webui
sudo cp deploy/nginx-webui-proxy.conf /etc/nginx/snippets/webui-proxy.conf
sudo cp deploy/nginx-webui-limits.conf /etc/nginx/conf.d/webui-limits.conf
sudo ln -s /etc/nginx/sites-available/webui /etc/nginx/sites-enabled/webui
sudo nginx -t && sudo systemctl reload nginx
sudo systemctl daemon-reload && sudo systemctl enable --now webui
```

TLS: `sudo certbot certonly --webroot -w /var/www/certbot -d ДОМЕН -d www.ДОМЕН`,
продление само по `certbot.timer`.

Копии рабочих конфигов держатся в `deploy/`: в `/etc` лежат экземпляры, которые
вне репозитория, поэтому правятся здесь и раскладываются по местам.

### Инфраструктура уровня машины

* **Беспарольный sudo сужен** с `NOPASSWD:ALL` до списка конкретных команд
  (`infra/sudo-allowed.list` — источник истины, применяется скриптом с проверкой
  `visudo -c` до установки). Сознательно **не включены**: правка юнитов systemd,
  установка пакетов с произвольными доводами и утилиты общего назначения с
  произвольными путями (`tee`, `cp`, `sed`, `chmod`, интерпретаторы) — любая из
  них равносильна полному root. Установка пакетов разрешена обёрткой, которая
  принимает **только имена** пакетов: у `apt-get install` есть
  `-o ...::Pre-Invoke` и локальные `.deb`, то есть произвольный код от root.
* Скрипт, разрешённый в sudoers, ставится владельцем root и **без права записи
  пользователю**: иначе разрешение на него равносильно разрешению запускать
  от root любой код.
* **Резервное копирование базы** — ежедневный `pg_dump` текстовым SQL с gzip
  (восстанавливается `psql`, поэтому не требует `pg_restore`, которого в
  разрешённых командах нет), еженедельная проверка восстановления, 14 копий
  плюс 3 последних в каталоге для забора по SFTP. Копии на том же диске от его
  отказа не спасают — забирать наружу.
* Фоновая уборка в приложении раз в час: старые метрики, просроченные сессии,
  попытки входа старше недели. Уборка не должна ронять приложение — исключения
  глушатся.

## 15. Правила работы

Порядок, по которому ведётся сам проект. Он же переносится в `CLAUDE.md` новой
копии.

### Чего делать нельзя

1. **Не удалять файлы** без явной просьбы. Файл кажется лишним — сначала спросить.
2. **Не добавлять в Git бинарники и артефакты сборки** — `.exe`, `.dll`, `dist/`,
   `build/`, `node_modules/`.

### Рабочий процесс

1. **В начале сессии — прочитать `result.md`**: на чём остановились, что в работе.
   При необходимости заглянуть в `log.md` и в план направления.
2. **Текущий ход работ — в `result.md`**, туда же документирование.
   В `CLAUDE.md` истории сессий не добавлять, он должен оставаться компактным.
3. **Новое правило — только с подтверждения**: спросить, записывать ли,
   и при согласии добавить в нужный раздел `CLAUDE.md`.
4. **Технический долг — в `tech_debt.md`, тоже с подтверждения**, в формате
   «что не так → чем грозит → как закрывается». Закрытый долг не удаляется —
   переносится в раздел «Закрыто» с датой и хэшем коммита.
5. **Перед изменениями и после них** убедиться, что проект в рабочем состоянии.
6. **Git:** небольшие логичные коммиты; по завершении задания коммит и пуш
   без запроса подтверждения, отчёт — хэш и краткое сообщение.
7. **Выполнять задание целиком**, без промежуточных вопросов.
8. **Журнал `log.md`:** новая задача дописывается **вверх** списка до начала
   работы (дата, название, статус «в работе», суть); по завершении — статус,
   хэши коммитов, краткий «Ход».
9. **Проверять интерфейс на сервере, а не только сборкой.**
10. **Папка `exchange/` не версионируется**: обмен, рабочие материалы, бэкапы.
    Новый промежуточный файл создаётся сразу там, а не в корне.
11. **Открытые вопросы — в `current_questions.md`**, только незакрытые: решённый
    вопрос удаляется, а результат уходит по месту (правило, архитектура, долг).
12. **Новую проверку сперва прогнать на дефекте, который она должна ловить.**
    Тест, который не падает на сломанном коде, не доказывает ничего — а выглядит
    как доказательство.
13. **Упавшая проверка сперва проверяется сама.** Прежде чем править продукт по
    красному результату стенда, убедиться, что красным его сделал продукт,
    а не оснастка.
    ⚠️ `pgrep -f <имя>` находит сам себя: строка поиска попадает в командную
    строку `bash -c`, и «процесс ещё жив» показывается там, где никого нет.
    Ждать выхода процесса опросом `pgrep` нельзя — гасить по PID и проверять
    результат по делу: ответом на запрос, появившимся файлом, строкой в логе.
14. **Правка обработчика кнопки проверяется нажатием кнопки, а не открытием окна.**

### Проверки

`pytest` в проекте нет: пробники лежат в `tests/` и запускаются вручную —
`.venv/bin/python tests/<файл>.py`. Каждый перед сдачей прогонялся на прежнем,
сломанном коде и падал на нём (правило 12). Что проверяется пробниками:
разбор длинной строки JSON, отвязка запуска от соединения браузера, сведение
повторов в стенограммах, окна тарифного плана, разбор событий расхода.

Обязательный минимум ручной проверки перед сдачей: страница открывается, консоль
без ошибок, вёрстка не поехала, `/healthz` отвечает `ok`, кнопка, которую правили,
нажата.

## 16. Порядок сборки

Проверяемые вехи, каждая заканчивается работающим состоянием:

1. **Каркас.** venv, FastAPI, `healthz`, служба под systemd, nginx с префиксом
   и TLS. Проверка: `/Claude/healthz` отвечает через браузер.
2. **База и вход.** `schema.sql`, пул, засев, argon2id, серверные сессии,
   обязательная смена пароля, ограничение частоты. Проверка: вход, выход,
   повторный вход, перебор упирается в ограничение.
3. **Дизайн-система.** `base.html`, токены, панель разделов, тёмная тема.
4. **Драйвер и чатики.** Запуск `claude`, разбор потока, сохранение расхода,
   продолжение по `--resume`, заголовок по первой реплике.
5. **Проекты.** Каталоги, темы, `allow_bash`, запреты инструментов и путей,
   файлообмен. Проверка: команда без флага **не** выполняется, файл настроек
   **не** читается.
6. **Фоновые запуски.** Вынос работы в задачу приложения, SSE с позиции,
   переподключение. Проверка: уйти на другую вкладку посреди ответа и вернуться.
7. **Дашборд и расход.** Метрики, история, окна по стенограммам, запасной
   источник, поиск, журнал, экспорт.
8. **Перезапуск из интерфейса** и перенос ключей под root.

## 17. Грабли одним списком

* `--allowed-tools` авто-одобряет, но **не запрещает**; запрет — только
  `--disallowed-tools`, и всё семейство `Bash`/`BashOutput`/`KillShell` сразу.
* В правиле по пути **двойной слеш**: `Read(//home/...)`. С одним слешем правило
  молча не действует.
* `--add-dir` — рабочая область, а не граница: `Read` читает любой путь.
* При `allow_bash` запрет по пути обходится командой `cat`. Настоящая граница —
  только другой пользователь или контейнер.
* `asyncio.StreamReader.readline()` падает на строках длиннее 64 КиБ, а движок
  их выдаёт постоянно.
* `StreamingResponse`, внутри которого запускается работа, умирает вместе с
  вкладкой браузера и уносит несохранённый ответ.
* В `modelUsage` есть вспомогательная модель; первый ключ брать нельзя.
* В стенограммах один и тот же `usage` повторён в нескольких строках одного
  ответа — сводить по `requestId + message.id`.
* Остаток по подписке программно недоступен; предел задаётся в настройках
  и подбирается наблюдением.
* `proxy_buffering off` и `X-Accel-Buffering: no` — без них поток приходит разом.
* `HOME` в юните — без него `claude` не найдёт учётные данные.
* Перезапуск службы гасит контрольную группу целиком, вместе с запущенным
  `claude`: ставить в очередь и ждать завершения ответов.
* `www` и основное имя — разные cookie: уводить редиректом, а не обслуживать оба.
* `pgrep -f <имя>` находит сам себя.
* Форма нового проекта транслитерирует имя в slug и создаёт каталог: для уже
  существующего каталога заводить запись в таблице напрямую.
