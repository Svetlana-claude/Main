# Кнопка доступа к ноуту — установка и использование

Помощник под Windows 10/11, который по нажатию кнопки поднимает **обратный SSH-туннель
ноут → ваш сервер вашим ключом**. Пока кнопка включена, вы заходите на ноут **сами**, со
своего устройства, через сервер. Закрыли окно — доступа нет.

**Чего эта программа не делает:** не кладёт ничьих ключей в ноут, не исполняет команд из
сети, не обновляет себя по сети, не заводит службу и не прописывается в автозапуск. Вход на
ноут решает только тот ключ, который **вы сами** положите в sshd ноута (шаг 1).

```
  ваше устройство  --ssh-->  сервер  --обратный туннель-->  ноут (sshd на 127.0.0.1)
```

---

## Как это безопасно

- Проброс на сервере слушает **только `127.0.0.1` сервера** — дойти до него можно, лишь уже
  войдя на сервер под вашей учёткой. Снаружи порт туннеля не виден.
- sshd ноута слушает **только `127.0.0.1` ноута** и пускает **только по ключу** (пароль
  выключен). Единственный авторизованный ключ — ваш.
- Туннель держится, **пока открыто окно и нажата кнопка**. Ни службы, ни автозапуска.

---

## Быстрый путь: всё одним файлом

`knopka-nastrojka.cmd` (копия — в «Файлах проекта») делает шаги 1, 2 и 4 и заполняет поля
программы сам: двойной щелчок, «Да» на запрос прав администратора. Ключ входа на ноут —
единственный, ключ Claude на сервере (`~/.ssh/noutbuk_vhod`, вход — `ssh noutbuk`), с пометкой
`from="127.0.0.1,::1"`; все прежние ключи из файла ключей ноута убираются. Ключ туннеля, если уже есть, не меняется, а только сверяется с сервером.
Служба sshd включается при загрузке (иначе после перезагрузки туннелю не к чему вести), входящий
порт 22 в брандмауэре закрывается. В конце окно показывает, что получилось. Ниже — то же вручную.

## Шаг 1 (один раз). Подготовить ноут

Запустите **PowerShell от администратора** на ноуте.

**1.1. Поставить OpenSSH (клиент и сервер), если их нет:**

```powershell
Add-WindowsCapability -Online -Name OpenSSH.Client~~~~0.0.1.0
Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
```

**1.2. Запереть sshd ноута на loopback и перевести на вход по ключу:**

```powershell
Set-Service sshd -StartupType Manual
Start-Service sshd
$cfg = 'C:\ProgramData\ssh\sshd_config'
$t = Get-Content $cfg -Raw
if ($t -notmatch '(?m)^ListenAddress 127\.0\.0\.1') { $t = "ListenAddress 127.0.0.1`r`n" + $t }
$t = $t -replace '(?m)^#?\s*PasswordAuthentication.*', 'PasswordAuthentication no'
$t = $t -replace '(?m)^#?\s*PubkeyAuthentication.*',   'PubkeyAuthentication yes'
Set-Content $cfg -Value $t -Encoding ascii
Restart-Service sshd
```

**1.3. Положить ВАШ ключ входа на ноут.** Ключ, которым вы будете заходить на ноут со своего
устройства (не путать с ключом туннеля из шага 3). Его **открытую** часть — в
`administrators_authorized_keys`, если ваша учётка в «Администраторах», иначе в
`C:\Users\<вы>\.ssh\authorized_keys`:

```powershell
# пример для учётки-администратора
$ak = 'C:\ProgramData\ssh\administrators_authorized_keys'
Add-Content $ak -Value 'ssh-ed25519 AAAA... ваш-ключ-входа' -Encoding ascii
icacls $ak /inheritance:r /grant "*S-1-5-32-544:F" /grant "*S-1-5-18:F"
```

## Шаг 2 (один раз). Ключ туннеля на ноуте

Этим ключом ноут **входит на сервер**, чтобы установить туннель. Создайте его на ноуте
(обычный PowerShell, без админа):

```powershell
ssh-keygen -t ed25519 -f $env:USERPROFILE\.ssh\knopka_tunnel -N '""'
type $env:USERPROFILE\.ssh\knopka_tunnel.pub   # покажет открытую часть
```

## Шаг 3 (один раз). Авторизовать ключ туннеля на сервере

Это делаете **вы на своём сервере** (программа сервер не трогает). Добавьте **открытую**
часть ключа туннеля (`knopka_tunnel.pub` из шага 2) в `~/.ssh/authorized_keys` вашей учётки
на сервере. Можно сузить права ключа — например запретить ему шелл и разрешить только
проброс (`restrict` снимает всё, явный `port-forwarding` оставляет туннель):

```
restrict,port-forwarding ssh-ed25519 AAAA... tunnel-ноута
```

Проверьте, что на сервере в `sshd_config` разрешён проброс (по умолчанию да):
`AllowTcpForwarding yes`. **`GatewayPorts` включать не нужно** — проброс остаётся на
loopback сервера, так и задумано.

## Шаг 4 (один раз). Пришпилить сервер в known_hosts (рекомендуется)

Чтобы ноут не дал себя перенаправить на подставной сервер, положите рядом файл `known_hosts`
с ключом **вашего** сервера и укажите его в программе. Получить строку ключа:

```powershell
ssh-keyscan -p <порт> <адрес-сервера> > $env:USERPROFILE\.ssh\knopka_known_hosts
```

(Сверьте отпечаток с тем, что видите при обычном входе на сервер.)

---

## Шаг 5. Настроить и включить программу

Собрать и запустить `KnopkaDostup.exe`, заполнить поля:

| Поле | Что вписать |
|---|---|
| Сервер / Порт | адрес и SSH-порт вашего сервера |
| Учётка | ваша учётка на сервере |
| Туннель | свободный порт на сервере, например `2222` |
| Ключ | путь к `knopka_tunnel` (закрытый, из шага 2) |
| known_hosts | путь к файлу из шага 4 (можно оставить пустым) |

Нажмите **«Открыть доступ»**. Лампочка зелёная — сервер подтвердил туннель; жёлтая — соединяется
(если жёлтая дольше 30 с — связь до сервера не доходит, чаще всего мешает VPN). Закрыли окно —
ssh гаснет вместе с программой, как бы она ни закрылась.

## Как заходить на ноут

Со своего устройства сначала на сервер, оттуда — на ноут через проброшенный порт:

```bash
ssh <вы>@<сервер>                                  # вошли на сервер
ssh -p 2222 <учётка-Windows-на-ноуте>@127.0.0.1    # прыгнули на ноут
```

Или одной командой с прыжком:

```bash
ssh -J <вы>@<сервер> -p 2222 <учётка-Windows>@127.0.0.1
```

Закончили — нажмите **«Закрыть доступ»** или закройте окно.

## Важно про SketchUp и Adobe

Это **консольный** доступ (SSH). Рисовать в SketchUp и Adobe по нему нельзя — для
графики нужен **удалённый рабочий стол**. Для той задачи см. памятку
`dostup-k-noutu.pdf` (Tailscale + RDP) в «Файлах проекта» темы «Безопасность».
Эта кнопка хороша, чтобы попасть на ноут в консоль: запустить задачу, поправить
настройку, забрать файл.

## Сборка

На машине с .NET 9 SDK (годится и Linux-сервер), в этой папке:

```
dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableWindowsTargeting=true
```

Готовый `KnopkaDostup.exe` — в `bin\Release\net9.0-windows\win-x64\publish\`, копия — в
«Файлах проекта» (`bezopasnost/downloads/`). Файл один, ≈ 130 МБ, .NET на ноуте ставить не
нужно.
