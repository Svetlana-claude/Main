# Картина сервера до установки аудита

Веха 0 плана (`plan-bezopasnost.md`, §10): снять состояние **до** того, как
что-либо ставится и правится. Без этого `PUB_TCP` берётся «из головы», а §5
инструкции требует брать по факту — и, как выяснилось, по факту тут несколько
вещей, которые аудит поймал бы в первую же ночь.

Снято 12.09.2026, `Ubuntu 24.04 LTS`, ядро `6.8.0-31-generic`.
Всё собрано **без root**: проверки, требующие `sudo`, помечены как непроверенные.

---

## 1. Что нашлось сразу

### ⚠️ Автообновления включены, но выключены

```
APT::Periodic::Update-Package-Lists "0";
APT::Periodic::Unattended-Upgrade "0";
```

Пакет `unattended-upgrades` установлен, служба есть — а в `20auto-upgrades`
нули. Это дословно та ситуация, о которой предупреждает §5 шаг 5 инструкции:
«служба активна, а в конфиге нули — годами не ставится ничего».

Подтверждается тремя независимыми признаками:

| Признак | Значение |
|---|---|
| Ожидает обновлений | **354** |
| из них security | **197** |
| Каталог `/var/log/unattended-upgrades/` | **пуст** — не отработал ни разу |
| Ядро | `6.8.0-31-generic` — стартовое для 24.04, апрель 2024 |

То есть машина не обновлялась с установки. Признак «требуется перезагрузка» при
этом не выставлен — он и не может быть выставлен: ставить было нечему.

### ⚠️ Вход по SSH паролем разрешён

Вопрос 1 из плана закрыт — проверкой делом, а не чтением конфига (`sshd -T`
без root не читается, а `50-cloud-init.conf` закрыт на чтение):

```
$ ssh -o PubkeyAuthentication=no -o NumberOfPasswordPrompts=0 mokeeva@127.0.0.1
mokeeva@127.0.0.1: Permission denied (publickey,password).
```

В скобках — методы, которые сервер **объявляет сам**. `password` там есть,
значит парольный вход включён.

Отсюда прямое следствие, и оно важнее самого аудита: §11 инструкции говорит,
что **беспарольный `sudo` при парольном входе недопустим** — подбор пароля даёт
root без единого дополнительного секрета. У нас беспарольный набор есть
(`infra/sudo-allowed.list`), и в нём обёртки, каждая по существу сужённый root.

`PermitRootLogin` проверить не удалось: в `/etc/ssh/sshd_config` стоит `yes`, но
`Include` идёт раньше этой строки, а OpenSSH берёт **первое** встреченное
значение — то есть решает `50-cloud-init.conf`, который без root не читается.
Проверяется вами одной командой:

    sudo sshd -T | grep -E 'permitrootlogin|passwordauthentication|maxauthtries'

### ⚠️ fail2ban не установлен

При открытом наружу 22-м порте и разрешённом парольном входе подбор ничем не
ограничен. `iptables-persistent` тоже не установлен — значит правила файрвола
сейчас негде закрепить, они не переживут перезагрузку.

## 2. Слушают наружу

Взято по факту (`ss -tulnH`), как требует §5 шаг 2:

```
tcp 0.0.0.0:80     tcp [::]:80      nginx
tcp 0.0.0.0:443    tcp [::]:443     nginx
tcp *:22                            sshd
udp 0.0.0.0:51820  udp [::]:51820   WireGuard
```

Отсюда значения для `config.sh`:

```bash
SSH_PORT=22
PUB_TCP="80,443"
PUB_UDP="51820"        # параметра нет в инструкции, добавляется (см. план, §5)
```

⚠️ **`ss` печатает 22-й порт как `*:22`, а не `0.0.0.0:22`.** Ровно ловушка из
§10 инструкции: фильтр по `0.0.0.0` такой сокет не увидит и не заметит этого.
Проверка «слушают наружу, но закрыты файрволом» обязана смотреть на все три
написания — `0.0.0.0`, `*` и `[::]`.

PostgreSQL и uvicorn слушают петлю и наружу не смотрят — так и должно быть.

## 4. Чего не проверить без root

Собирается на вехе 0 вместе с вами либо уже самим аудитом после установки:

* `sudo iptables -S INPUT` и `ip6tables` — политика и правила. Скорее всего
  политика `ACCEPT` и правил нет: `iptables-persistent` не установлен;
* `sudo sshd -T` — действующие `PermitRootLogin`, `MaxAuthTries`, `AllowUsers`;
* `/etc/shadow` — алгоритм хэша пароля. §11 напоминает, что панель хостера
  умеет записать пароль `root` алгоритмом `$1$` (MD5), и такое живёт годами;
* `crontab` других пользователей, `/etc/sudoers.d/*`, отпечатки ключей
  в `authorized_keys` — всё это собирает `collect.sh` от root.

## 5. Что это меняет в плане

Порядок вех остаётся, но первые два шага теперь понятны точно:

1. **Автообновления — раньше всего остального.** Это одна правка
   `20auto-upgrades` и одна установка 197 security-обновлений; аудит здесь ни
   при чём, а дыра открыта прямо сейчас. Перед установкой — выгрузка базы
   (`infra/pg-backup.sh`), после — вероятна перезагрузка ради нового ядра,
   и вот тут пригодятся `pre-reboot.sh` / `post-reboot-check.sh` из инструкции.
2. **Парольный вход — решение за вами** (вопрос 2 плана). Пока он открыт,
   беспарольный `sudo` остаётся слабым местом всей конструкции.
3. **fail2ban и `iptables-persistent` ставятся** — их нет вовсе, значит веха 3
   без них не имеет смысла: применённые правила не переживут перезагрузку.
