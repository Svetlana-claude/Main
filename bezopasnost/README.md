# Ночной аудит безопасности

Набор периодических проверок для этого сервера: раз в сутки снимается состояние
машины, сверяется с утверждённым эталоном, часть отклонений устраняется
автоматически, остальное уходит в отчёт.

Основа — инструкция `security-control.md` (загружена в проект). Здесь описано
только то, **чем эта установка от неё отличается** и как ею пользоваться.
Замысел целиком, включая вкладку в веб-интерфейсе, — `plan-bezopasnost.md`.
Состояние машины до установки — `sostoyanie-do.md`.

| Файл | Роль | Права |
|---|---|---|
| `config.sh` | единственный файл, который правят под сервер | — |

| `tests/check-diff.sh` | проверка сверки на поддельных снимках | обычные |

## Раскладка: код отдельно, состояние отдельно

Инструкция кладёт всё в один каталог `/opt/secaudit` и делает владельцем учётку
аудита. **Здесь так нельзя.** Приложение и агент работают от `mokeeva`; каталог,
доступный `mokeeva` на запись, плюс разрешение запускать оттуда `collect.sh` от
root — это беспарольный root целиком. Тот же довод, по которому обёртка
`webui-vpn` не запускает скрипты из `vpn-server/`.

| Путь | Владелец | Что там |
|---|---|---|
| `bezopasnost/` | `mokeeva` | исходники — правятся здесь |
| `/opt/secaudit/*.sh`, `config.sh` | `root:root` | рабочая копия |
| `/opt/secaudit/baseline/` | `root:root` | эталон: пишет только root через обёртку |
| `/opt/secaudit/quarantine/` | `root:root 700` | изъятое |
| `/var/lib/secaudit/` | `mokeeva 700` | снимки, отчёты, `audit.log` |

**Следствие:** правка скрипта здесь вступает в силу только после

    sudo bash infra/install-root-helpers.sh

## Отличия от инструкции

Каждое внесено по конкретной причине, а не для красоты.

1. **`PUB_UDP` и открытие UDP в `apply-firewall.sh`.** В инструкции UDP не
   открывается вовсе — первое же применение правил отрезало бы WireGuard
   (`51820/udp`) молча. Ровно ловушка из её же §10.
2. **`TRUSTED_IFACES="wg0"`.** Клиент с полным туннелем ходит к серверу по
   `10.8.0.1`, это INPUT с `wg0`. Без правила панель по туннелю не открылась бы.
3. **Разделение `BASE` и `STATE`** — см. выше.
4. **`remediate.sh` не принимает путь к снимку**, а делает свежий сам. В
   инструкции путь приходит доводом, а снимок лежит в каталоге, доступном
   пользователю на запись: на вход root-скрипту попадали бы данные, которые
   можно подделать, и по ним он переносит файлы и гасит процессы.
5. **Файрвол не применяется автоматически, пока не применён руками хотя бы
   раз** (метка `backup/firewall-applied`). Иначе первый же ночной прогон на
   машине без файрвола включил бы default-deny без проверки доступа из второго
   окна — то есть ровно тем способом, которым теряют сервер.
6. **Сверка сокетов с правилами идёт и по UDP, и по всем трём написаниям
   адреса** (`0.0.0.0`, `*`, `[::]`), и **только при политике DROP**. Подробнее —
   в `tests/check-diff.sh`, там каждый случай оформлен проверкой.
7. **`LOGIN_SRC` пишет сеть /24**, а не адрес: иначе свой вход с домашнего
   провайдера каждый раз выглядел бы как вход с нового адреса.
8. **Пустой снимок считается ошибкой.** Молчащий отказ `sudo` даёт пустой
   снимок, а отчёт по нему выглядит спокойным — самый опасный вид отчёта.
9. Мелочь: в секции `SYSTEMD` исправлено `find ... -name '*.service' -o -name
   '*.timer'` — без скобок `-o` разваливает условие, и вторая половина работает
   не с теми путями.

## Проверки

    bash bezopasnost/tests/check-diff.sh

Десять утверждений на поддельных снимках. Каждое прогонялось на дефекте,
который обязано ловить, — и падало на нём:

| Дефект | Что даёт |
|---|---|
| сверка только по TCP (как в инструкции) | 3 провала: UDP-порт не найден |
| убрана проверка политики DROP | 2 провала: до установки файрвола все порты объявлены отрезанными |
| `sort -un` перед `comm` | 2 провала: `comm` ругается на порядок и врёт результатом |

⚠️ Первая попытка внести первый дефект **не внеслась** — `sed` не учёл отступ,
и проверка осталась зелёной. Зелёный результат тогда дала оснастка, а не код.
Поэтому дефект вносится и **проверяется глазами** (`grep -n`), прежде чем
верить результату.

## Порядок установки

Расписан по вехам в `plan-bezopasnost.md`, §10. Коротко и по-прежнему в силе:
**сперва доступ, потом замок** — обратный порядок отрезает от машины.

Холостой прогон в стороне от боевой установки:

    BASE=/tmp/sec-probe STATE=/tmp/sec-probe bash audit.sh
