# Инфраструктура сервера

Настройки уровня машины, не относящиеся к конкретному проекту.

| Файл | Назначение |
|---|---|
| `sudo-allowed.list` | **источник истины** по беспарольным командам sudo |
| `apply-sudo.sh` | применяет список в `/etc/sudoers.d/010-mokeeva` |
| `webui-deploy.sh` | раскладка конфигов nginx, ставится в `/usr/local/sbin/webui-deploy` |

---

## Как добавить команду

1. Агент предлагает строку и объясняет, зачем она нужна и что даёт.
2. Вы разрешаете.
3. Строка добавляется в `sudo-allowed.list` в нужный раздел, с комментарием.
4. Применение:

       sudo bash infra/apply-sudo.sh

   Предварительный просмотр без установки:

       sudo bash infra/apply-sudo.sh --dry-run

Скрипт проверяет результат через `visudo -c` **до** установки и сохраняет прежнюю
версию рядом. Битый `sudoers` способен отрезать доступ к sudo целиком, поэтому
без успешной проверки ничего не меняется.

---

## Что даёт сужение, а что нет

Это стоит понимать точно, иначе легко решить, что защита сильнее, чем есть.

**Даёт.** Защиту от случайной ошибки. Опечатка в пути, неверный аргумент, лишний
`rm` — всё это больше не выполнится от root, потому что попросту не разрешено.
Набор действий агента стал перечислимым и виден в одном файле под контролем версий.

**Не даёт.** Границы безопасности от намеренного действия. Любая возможность
писать в `/etc` или устанавливать пакеты от root равносильна root: systemd-юнит
исполняется от root, а установка пакета запускает сценарии сопровождающего.
Поэтому в список **сознательно не включены**:

* `apt-get install` и любая установка пакетов;
* правка юнитов systemd;
* `tee`, `cp`, `sed`, `chmod`, `chown`, `dd` с произвольными путями;
* `su`, `bash`, `sh`, `python` и прочие интерпретаторы;
* `visudo` и правка самого `/etc/sudoers.d`.

Всё это запускаете вы сами, с паролем. Полный root у вас сохраняется:
`mokeeva` входит в группу `sudo`, а стандартное правило `%sudo ALL=(ALL:ALL) ALL`
никуда не делось. Сужается только беспарольный набор — тот, которым пользуется
агент, не имеющий терминала для ввода пароля.

Следствие в работе: когда понадобится новый пакет (например `certbot` для перехода
на Let's Encrypt), агент попросит вас выполнить установку. Это ожидаемая цена
такого разделения.

## Скрипт раскладки nginx

`webui-deploy.sh` принадлежит root и недоступен пользователю на запись — иначе
разрешение `sudo webui-deploy` означало бы разрешение запускать от root любой код.

Отсюда: правка файла в репозитории сама по себе ничего не меняет. Новую версию
устанавливаете вы:

    sudo install -o root -g root -m 0755 infra/webui-deploy.sh /usr/local/sbin/webui-deploy

Скрипт раскладывает только три файла nginx по закрытому списку пар
«источник — назначение», проверяет `nginx -t` и при ошибке откатывается
из резервной копии.

## Проверка текущего состояния

    sudo -l                          # что разрешено без пароля
    sudo -n true                     # должно отказать: полный root без пароля закрыт
    sudo -n systemctl is-active webui  # должно сработать
