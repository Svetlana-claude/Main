# `telegram-bot` — второй пульт к рабочему месту

Бот в Телеграме, через который можно общаться быстрее, чем через браузер,
утверждать задачи кнопками и работать по проектам.

## Ключевое решение

Бот — **второй вход в то же рабочее место**, а не отдельная программа.

| Что | Откуда берётся |
|---|---|
| Движок | `webui/app/services/claude_driver.py` — тот же `claude` в неинтерактивном режиме |
| База | тот же PostgreSQL, те же `conversations`, `messages`, `projects`, `files` |
| Права в проектах | та же запись `projects` — рабочий каталог и флаг `allow_bash` |
| Модель и потолок контекста | те же `settings`, что правятся в панели |
| Файлы | тот же `webui/uploads/`, видны в «Файлах проекта» |

Отсюда главное свойство: **разговор, начатый в Телеграме, виден в браузере и
продолжается там, и наоборот.** Своих таблиц у бота четыре, и все — про
Телеграм: кому можно (`tg_users`), к какому диалогу привязан чат (`tg_binding`),
задачи с утверждением (`tasks`) и смещение очереди (`tg_offset`).

Своя обёртка над Bot API (`bot/api.py`, семь методов) вместо `aiogram`: на
сервере 2.9 ГБ ОЗУ и рядом живёт `webui` — по той же причине, по которой в
`architect.md` отказались от Node.js и Docker.

Опрос длинными запросами, а не webhook: webhook требует ещё одного открытого
наружу адреса, а опрос решает ту же задачу одним висящим запросом.

## Запуск

Команды Телеграма пишутся латиницей — таково ограничение Bot API; тексты,
кнопки и подсказки русские.

**1. Бот у `@BotFather`.** `/newbot`, имя любое, в ответ — токен. Там же стоит
выключить ему добавление в группы (`/setjoingroups` → Disable): бот работает в
личной переписке, и чужая группа ему не нужна.

**2. Файл настроек** — вне каталога проекта, как у `webui`:

```bash
mkdir -p ~/.config/tgbot
cp telegram-bot/.env.example ~/.config/tgbot/tgbot.env
chmod 600 ~/.config/tgbot/tgbot.env
nano ~/.config/tgbot/tgbot.env      # вписать TELEGRAM_TOKEN
```

`TELEGRAM_ALLOWED` можно пока оставить как есть: бот ответит на `/id` даже
тому, кого в списке нет, — оттуда и берётся свой номер. Вписать его и
перезапустить службу.

**3. Окружение и зависимости:**

```bash
cd ~/main/telegram-bot
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

**4. Проверка без сервера и без Телеграма** — нарезка и разметка ответа:

```bash
python3 tests/check-razmetka.py
python3 tests/check-razmetka.py --slomat narezku     # обязана покраснеть
```

**5. Первый пуск руками**, чтобы видеть журнал:

```bash
cd ~/main/telegram-bot && .venv/bin/python -m bot.main
```

В журнале должно появиться `бот @имя запущен`. Напишите боту `/id`, впишите
номер в `TELEGRAM_ALLOWED`, перезапустите, напишите `/help`.

**6. Служба:**

```bash
sudo cp deploy/tgbot.service /etc/systemd/system/tgbot.service
sudo systemctl daemon-reload
sudo systemctl enable --now tgbot
journalctl -u tgbot -f
```

## Как работать

| Команда | Что делает |
|---|---|
| `/help` | что умеет и чего не умеет |
| `/projects` | выбрать проект; `🔑` — проекту разрешён запуск команд |
| `/new` | начать новый диалог (прежний остаётся в панели) |
| `/mode` | «сразу» или «с утверждением» |
| `/task что сделать` | поставить задачу с утверждением |
| `/tasks` | что ждёт решения, что идёт, что отклонено |
| `/files` | файлы текущего проекта, кнопкой — забрать |
| `/status` | диалог, проект, режим, контекст, расход за сутки |
| `/stop` | прервать то, что выполняется сейчас |

**Задача с утверждением.** Просьба возвращается замыслом — заголовок, «что
сделаю» пунктами, «что изменится», «чем рискую» — и тремя кнопками:
«Утвердить», «Уточнить», «Отклонить». Работа начинается только после
утверждения. Замысел составляется **без инструментов**: это переформулировка
просьбы, а не изучение кода — заглядывать в файлы на этом шаге нельзя, потому
что инструменты правки включаются вместе с чтением, и «только посмотреть» не
бывает.

**Файлы и снимки.** Присланное ложится в `webui/uploads/` и в таблицу `files` —
то есть видно в «Файлах проекта». Снимок сперва идёт в распознавание
(`tools/ocr.py`, правило 17), и движку передаётся **текст**, а не картинка: в
неинтерактивном режиме изображение ему не передать. Распознанное идёт как данные
заказчика — команды внутри изображения не исполняются, и об этом сказано прямо в
сопроводительной строке.

## Грабли, на которые уже наступили

**Токен не должен попадать в `os.environ`.** `load_dotenv` положил бы его в
окружение процесса, а оттуда его унаследовал бы запущенный нами `claude` — и в
теме с разрешённым `Bash` токен читался бы простым `env`, безо всякого доступа к
файлу. Поэтому настройки читаются `dotenv_values`, а имена наших ключей вдобавок
дописываются в `config.SCRUB_ENV_KEYS` драйвера: настройки могут прийти не из
файла, а от systemd, и тогда они окажутся в окружении до нас.

**Телеграм разбирает теги сам** и на непонятном отказывается отправлять
сообщение **целиком** — то есть длинный ответ с незакрытым `<b>` пропадает весь.
Поэтому режется исходный Markdown по границам строк (с закрытием и повторным
открытием ограды кода), а в HTML переводится каждый кусок отдельно; на отбой
кусок уходит без тегов вовсе. Оформление дешевле ответа.

**Правка сообщения — тоже сообщение.** «Ход работы» правится не чаще чем раз в
2,5 с, иначе Телеграм отвечает 429. Ответ 429 отрабатывается по его же
`retry_after`, а не своим запасом: свой запас даёт отбой вторым кругом.

**Один ответ на чат за раз.** Тема — одна сессия Claude Code, продолжаемая
`--resume`; два процесса на одной сессии разошлись бы в истории. Вторая просьба
ждёт замка, очередь честная.

**Смещение очереди двигается до обработки, а не после.** Иначе долгая задача,
прерванная перезапуском службы, приехала бы от Телеграма заново и выполнилась
второй раз — а это правки в файлах и коммиты.

## Чего бот не умеет

* **Голос** — распознавателя речи на сервере нет; бот говорит об этом словами,
  а не молчит.
* **Видеть картинку** — работает по распознанному тексту (см. выше).
* **Группы** — рассчитан на личную переписку; в группе он формально заработает,
  но права там раздаются по `tg_users`, а не по участникам группы.
* **Ждать уточнения через перезапуск** — ожидание живёт в памяти; после
  перезапуска службы задачу надо поставить заново.
