# Новый сайт для общения с Claude — устройство

Адрес — `https://mokeevasky.ru/Claude/v2`. Задание — `webui2/tz.md`. Отдельный
сайт: своя служба, своя база, свой вход. Старый сайт (`webui`, `/Claude/`) не
трогается и работает рядом.

## Стек

Python 3.12, FastAPI, страницы на шаблонах Jinja2, свой CSS и JS без сборки,
база SQLite. Пароль и код замка — argon2. Тема светлая (по ответу хозяйки,
вместо тёмной из ТЗ).

Вне проекта, права 600 (каталоги 700):

- `~/.config/webui2/webui2.env` — `SECRET_KEY`, `LOGIN`, `TIMEZONE`, при нужде
  `DB_PATH`. Путь меняется переменной `WEBUI2_ENV` (так делают проверки).
- `~/.local/share/webui2/site.db` — база.
- `~/.local/share/webui2/chat-room/` — пустая папка, в ней запускается Claude чата.
- `~/projects/<латиницей>/` — папки проектов (путь — `PROJECTS_DIR`).

## Запуск

Служба `webui2` (`/etc/systemd/system/webui2.service`, копия — `deploy/`):
uvicorn на `127.0.0.1:8002`, `--root-path /Claude/v2`, `UMask=0077`, включена
при загрузке. Перезапуск сайта не задевает старый.

nginx: правила в `/etc/nginx/snippets/webui2.conf` (копия —
`deploy/nginx-webui2.conf`), подключены строкой `include` в блоке
`mokeevasky.ru` файла `/etc/nginx/sites-available/webui` (копия —
`webui/deploy/nginx-webui.conf`). Префикс срезается; `/Claude/v2/login`
ограничен по частоте общей зоной `login`.

## Вход и защита

- **Первая настройка** (`/setup`) — пока в базе нет хозяйки. Пароль дважды, код
  замка дважды и код с телефона. Секрет кода с телефона заранее переносит
  `tools/prepare.py` из старого сайта в таблицу `setup` — поэтому заполнить
  форму может только хозяйка, QR заново не нужен. После настройки страница
  закрыта, секрет из `setup` стирается.
- **Вход** — два шага: логин и пароль → пропуск на 5 минут (подписан, внутри хвост
  хеша пароля — смена пароля гасит пропуска) → шесть цифр с телефона. Код
  принимается в окне ±30 с, повтор того же кода — нет (`users.totp_last`,
  условная запись).
- **Сессия** — таблица `sessions`, в куке `v2_session` подписанный номер
  (HttpOnly, Secure, SameSite=Lax, 12 часов). «Выйти» удаляет запись.
- **Подбор** — `login_fails`: 5 неудач с адреса за 15 минут закрывают вход,
  настройку, замок и смену пароля для этого адреса. Неудачи — неверный пароль,
  код с телефона, код замка, старый пароль.
- **Подделка запросов** — у сессии свой `csrf`, он во всех формах и в запросе
  замка; до входа — одноразовая кука `v2_pre` против поля формы. Вдобавок
  `Origin`/`Referer` должен совпадать с адресом сайта.
- **Замок** — признак `sessions.locked` на сервере. Под замком любая страница
  отдаёт только шторку с полем кода; код сверяет сервер. Вкладки узнают друг о
  друге через `localStorage` и сверяются с `/state`; при возвращении на вкладку —
  тоже.
- **Забыт пароль** — `tools/reset_login.py`: хозяйка и все входы удаляются,
  секрет кода с телефона возвращается в `setup`, сайт снова ждёт первой
  настройки (новый пароль и код замка, подтверждение — код с телефона).
  Разговоры и проекты не трогаются.
- **Смена пароля** — в «Настройках»: старый и дважды новый (от 10 знаков). Прочие
  сессии при этом закрываются.
- Время хранится в UTC, показывается по Москве (`local_time`).

## Чат

- **Запуск Claude** (`claude.py`): `claude -p` с потоком JSON и на входе, и на
  выходе; `--tools ""`, `--setting-sources ""`, `--disable-slash-commands`,
  `--strict-mcp-config`, свой короткий системный текст с правилами общения
  (`SYSTEM_PROMPT`). Папка — пустая `chat-room`. Переменные сайта (`WEBUI2_*`,
  `ROOT_PATH`, `SECRET_KEY`) в запуск не передаются. Беседа продолжается
  `--resume` по `conversations.session_id`. Модель — своя у разговора
  (`opus`/`sonnet`/`haiku`, по умолчанию `sonnet`), действует со следующего
  сообщения.
- **Фоновый ответ** (`chat.Run`, словарь `RUNS` в памяти): один запуск на
  разговор, от страницы не зависит. Куски текста раздаются слушателям потока
  `/chat/{id}/stream` (события `snapshot`, `delta`, `added`, `saved`, `done`).
  Ответ пишется в базу, когда ход закончен. Ушла со страницы — запуск идёт;
  вернулась — страница показывает накопленный текст и подключается к потоку.
- **Дописка**: пока запуск открыт, новое сообщение пишется в его stdin и
  становится следующим ходом того же запуска (проверено на настоящем Claude:
  отдельного запуска нет). В базу дописка попадает после ответа, к которому
  пришла, — так порядок в ленте верный; до того она видна из памяти запуска.
  Когда закончены все ходы, stdin закрывается и запуск завершается. Сообщение,
  пришедшее в этот миг, ждёт конца запуска и начинает новый.
- **Перезапуск сайта обрывает идущие ответы.** Счётчик — `chat.active_runs()`;
  ожидание перед перезапуском — на этапе 6 (настройки).
- **Лента**: последние 40 сообщений (`?n=` — больше, «Показать раньше»),
  обновляется фрагментом `/chat/{id}/feed`. Ответ — markdown через
  markdown-it-py с `html=False` (теги показываются текстом), таблицы в обёртке
  с прокруткой.
- **Название** — начало первого сообщения (до 60 знаков по слову). ✎ —
  переименование, корзина — удаление с вопросом «Удалить?» (идущий ответ
  гасится). Пустые разговоры не копятся: «Новый разговор» убирает прежние пустые.
- **Вес** — размер контекста последнего хода (`context_tokens`). Больше
  150 тыс. и молчание дольше 6 часов — подсказка начать новый разговор.
- **Поиск** (`/search`): `messages.norm` — текст строчными, «ё» как «е»;
  находятся сообщения, где есть все слова запроса, и в разговорах, и в темах
  (у темы — пометка проекта, ссылка ведёт в тему).
- Открытие вкладки — последний разговор (по `updated_at`).
- Ctrl+Enter (на Mac — Cmd+Enter) — отправить, Enter — новая строка (по просьбе хозяйки).
- На телефоне разговор на весь экран, список — по кнопке «‹ Разговоры»;
  отправка — кнопкой.

## Проекты

- **Проект** — строка `projects` и папка `~/projects/<имя латиницей>` (русские
  буквы переводятся, занято — `-2`, `-3`). Новый проект: папка, `downloads/`,
  `.gitignore` (секреты, тяжёлое, `downloads/`), `CLAUDE.md` с правилами общения
  (`app/project_rules.md`), свой git с подписью хозяйки (из `GIT_NAME`/`GIT_EMAIL`
  или из git самого сайта) и первым сохранением.
- **Тема** — разговор с `conversations.project_id` (колонку старые базы получают
  в `db.init`). Лента, дописка, модель, ✎ и корзина — общие с чатом
  (`/chat/{id}/…`), страница — `/projects/{pid}/t/{id}`. Новая тема — Opus.
- **Claude в теме** (`claude.project_argv`): папка проекта, обычные настройки,
  CLAUDE.md и память, без своего системного текста. Галочки:
  - без галочек — `--permission-mode acceptEdits`, команды (`Bash` и соседи)
    запрещены; за пределы папки — отказ (спросить пока некого,
    `--permission-prompts none`; вопросы — этап 5);
  - «Запускать команды» — то же, плюс `--allowed-tools Bash …`;
  - «Полный доступ» — `--permission-mode bypassPermissions`.
  Действуют со следующего сообщения. В любом режиме закрыты ключ и база сайта:
  `Read/Edit/Write(//…/webui2/**)` и команды, где упомянуты их папки или файлы
  (`claude.secret_deny`; проверено на настоящем Claude и в режиме полного
  доступа). Команды — защита по строке, обойти можно; настоящая стена — только
  отдельный пользователь для Claude.
- **Что делает** — строка под ответом: из `tool_use` в потоке
  (`claude.tool_status`: «Читаю …», «Правлю …», «Выполняю: …», «Ищу в файлах…»),
  пока пишет — «Пишу ответ…», в начале — «Думаю…». Событие `status` в потоке;
  `start` — новое сообщение внутри хода, черновой текст сбрасывается. События
  помощников (`parent_tool_use_id`) не показываются.
- **Удаление проекта** (корзина у названия): `delete_state` в базе.
  1. `checking` — разовый Claude (`claude.once`, без продолжения беседы) в папке
     проекта: команды, чтение и поиск можно, правка — нет. Пишет, что проект завёл
     вне папки (службы, cron, nginx, файлы).
  2. `ready` — список на странице `/projects/{pid}/delete`, «Да, удалить» /
     «Отмена». Пока идёт проверка или удаление, страница обновляется сама.
  3. `removing` — идущие ответы тем гасятся; Claude с полным доступом убирает
     ровно найденное (если «ничего нет» — не запускается) и последней строкой
     пишет «ИТОГ: всё убрано»; иначе — `unclear`, папка не тронута. Затем сайт
     удаляет папку (`projects.removable`: только внутри `~/projects`, не ссылка,
     не папка сайта и не вокруг неё) и проект с темами.
  `unclear` — не вышло, причина в `delete_report`; «Проверить снова» или
  «Отмена». Перезапуск сайта посреди проверки возвращает проект как был,
  посреди удаления — в `unclear`.

## Файлы проекта

- Показывается папка `downloads/` проекта: только обычные файлы прямо в ней —
  без скрытых, ссылок, подпапок и выхода из папки (`files.find`). Новые сверху,
  с размером и временем по Москве.
- **Загрузка** — до 512 МБ на файл, сразу несколько. Сначала проверяются вход и
  адрес страницы (до чтения тела), потом поле защиты формы. Файл пишется во
  временный скрытый `.upload-…` и кладётся под свободным именем жёсткой ссылкой
  (`files.place`): занято — «имя (2)». Имя чистится: без пути, управляющих
  знаков и точек в начале, до 200 байт. На странице — ход загрузки в процентах.
  nginx пропускает до 520 МБ (`client_max_body_size` в блоке сайта).
- **Просмотр**: текст (по расширению или если начало читается как UTF-8 без
  нулей) до 2 МБ открывается на сайте, `.md` — с разметкой (сырой HTML не
  проходит). **Скачивание** — всегда вложением, `application/octet-stream`,
  с `Content-Security-Policy: sandbox` и `nosniff`.
- На компьютере файлы — колонкой справа у проекта и темы; список обновляется,
  когда Claude закончил ход. Уже 1000 точек — колонка прячется, вместо неё
  ссылка «Файлы проекта» на отдельную страницу `/projects/{pid}/files`.
